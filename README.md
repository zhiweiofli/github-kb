# GitHub Knowledge Base (github-kb)

A filesystem-first approach to managing your personal GitHub knowledge base.

## What is this?

github-kb turns GitHub into a **searchable, ownable local knowledge system**.

Instead of relying on browser history or remote bookmarks, relevant GitHub projects are cloned into a fixed directory, summarized, and indexed in a single catalog file.

## Features

- **Search GitHub** via `gh` CLI (repos, issues, PRs)
- **Clone repositories** into organized local storage
- **Retrieve information** using local file tools
- **Maintain a catalog** as human-readable index

## Quick Start

### Prerequisites

```bash
# Install GitHub CLI
brew install gh

# Authenticate
gh auth login
```

### Usage

Use natural language or slash commands:

```
# Search for repositories
/search-github chatbot framework python

# Clone a repository
/clone-repo anthropics/claude-code

# Update the catalog
/update-catalog
```

## Philosophy

**Low complexity, high control.**

This skill favors:
- Filesystem ownership over cloud dependency
- Explicit structure over magic discovery
- Human-curated summaries over auto-generated content
- CLI-based search over complex APIs

The result is a durable, portable, and inspectable personal GitHub knowledge system.

## Non-Goals

- No mass crawling or scraping
- No vector databases or embeddings
- No private repo access without explicit auth
- No automatic summarization without reading source

## Issue 自动收录（DeepSeek）

**新入口：Add project Issue → DeepSeek 初评 → 项目卡 + 自动索引 → Git 提交 → Issue 回执。**

- [自动项目索引](projects/INDEX.md)：按用途、关键词找新收录的项目。
- [历史索引](INDEX.md)：保留原有收录；当前不批量迁移。
- [分析规则](rules/analysis.md)：定位、适用场景、能力、限制、再次考虑的条件。初评不等于试用。

### 启用与使用

1. 将本次 workflow、脚本、规则、Issue 模板及文档发布到默认分支。
2. 在仓库 Settings → Secrets and variables → Actions 添加 Secret `DEEPSEEK_API_KEY`。不要把密钥写进 Issue、代码或聊天。
3. 确保 Actions 有 contents/issues 写权限，默认分支允许 Actions bot 提交。
4. 仓库所有者使用 **Add project** 模板提 Issue，一次一个公开 GitHub 仓库，可填写关注原因。其他账号提的 Issue 不自动调用模型。
5. 成功后 Issue 自动关闭并附项目卡链接；失败查看 Actions 日志，在 **Run workflow** 输入 Issue 编号重试。

默认模型名 `deepseek-v4-flash`，可用仓库变量 `DEEPSEEK_MODEL` 调整。按 [官方变更记录](https://api-docs.deepseek.com/updates/)，该兼容名称当前路由至 V4.1 Flash（新名称 `deepseek-flash`）；项目卡记录 API 返回的实际模型名称。调用官方 API，非思考模式 + JSON 输出，每次最多 4000 输出 token。

向 DeepSeek 发送公开仓库元数据、README（最多 40000 字符）及 Issue 关注原因。不发送本地个人画像、MEMORY 或 KnowledgeBases 内容。本仓库公开，因此 Issue、关注原因和生成卡也公开，请勿填写私人工作信息。

重复收录已有项目会返回原卡，不重新消耗模型额度，也不覆盖人工修改。新增分析仅写 `projects/`；不克隆项目，不执行来源代码，不自动写概念知识库。并发 push 冲突或分支保护拒绝时本次失败，修复后重试即可。

### ChatGPT / Agent 如何复用

在 ChatGPT 项目指令或 Agent 的工作入口加入：“进行新项目选型时，先通过 GitHub MCP 读取 `zhiweiofli/github-kb` 的 README，并按其检索流程查找已关注的项目。” README 本身不会主动触发 MCP。

检索流程：
1. 从当前需求提取用途、能力、约束关键词。
2. 读取 `projects/INDEX.md`，并查询历史 `INDEX.md`，不要把新索引无命中等同于整个目录无候选。
3. 读取最相关的至多 3 张项目卡；历史条目直接参考其中的 GitHub 来源。
4. 说明匹配理由、限制、哪些仍未验证，并给出来源链接。准备实际采用时复核上游当前状态。
5. 用户的当前需求和明确反馈优先。目录是候选记忆，不是自动采用决定。
